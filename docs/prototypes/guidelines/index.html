Prototype System

FileFacet HTML 原型规范

用于统一原型外壳、页面层级、字号、交互状态和验收交付。新原型从共享外壳开始，再补充当前功能需要验证的内容。

当前规范
用户任务优先

页面围绕用户要完成的操作组织，关键入口、状态变化和反馈都应可直接操作。

共享外壳统一

左导、menubar、字号令牌和收起行为由共享资源维护，页面不复制这些结构。

验收状态完整

覆盖主路径、关键状态、必要异常和恢复方式，产品结论以用户验收为准。

1. 页面外壳

左导属于原型工作区，menubar 和窗口属于 FileFacet 展示区域。

原型导航从顶部贯穿到底部
FileFacet文件编辑显示窗口帮助
App 展示区域menubar 仅覆盖这一侧；左导收起后同步扩展

2. 共享资源与页面骨架

共享脚本必须先于页面脚本加载，确保导航、menubar 和菜单节点已经存在。

<link rel="stylesheet" href="../prototype-shell.css">

<body data-prototype-page="feature-id"
      data-prototype-subtitle="当前原型说明"
      data-prototype-file-menu="import">
  <template id="prototypePageActions">
    <section class="prototype-group">…页面专属状态按钮…</section>
  </template>

  <main class="desktop prototype-content prototype-app-surface">…</main>

  <script src="../prototype-shell.js"></script>
  <script>…页面专属交互…</script>
</body>
新增页面时，在 prototype-shell.js 的页面登记表中增加一次入口。所有原型会自动获得新链接和当前页高亮。

3. 字号与密度

相同语义使用相同层级；辅助信息保持可读。

语义字号共享令牌 / 使用规则
App 主体13px--prototype-shell-font-size
menubar12px--prototype-menubar-font-size
左导项目11px--prototype-navigation-font-size
辅助文字最低 11px--prototype-caption-font-size
区块标题13–16px按页面层级使用，避免用字号承担过多装饰
原型说明区14px可高于 App 主体，保持与模拟 App 的边界

4. 交互与状态

页面专属按钮进入左导；产品内部按钮保留在模拟 App 中。

原型应覆盖

  • 核心用户主路径 从入口到结果可以完整操作
  • 关键状态转换 进行中、成功、失败、撤销和恢复
  • 必要异常状态 权限、空结果、无效输入和离线
  • 导航生命周期 切换页面或分类后的状态清理

外壳约定

  • 单独按 P 收起或展开左导
  • data-prototype-app-menu="true" 启用 App 菜单
  • data-prototype-file-menu="import" 启用导入菜单
  • 页面脚本使用稳定 ID 不要依赖显示文案判断业务状态

5. 交付前检查

静态检查确认结构完整；产品行为继续由用户验收。

  • 当前页面已经登记并正确高亮
  • 共享 CSS 和 JS 路径可解析
  • 页面中没有重复 ID
  • 页面脚本通过 node --check
  • 旧底部演示菜单已经移除
  • menubar 仅覆盖右侧 App 区域
  • 输入控件聚焦时 P 不触发
  • git diff --check 通过
