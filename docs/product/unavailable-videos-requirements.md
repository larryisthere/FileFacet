# 不可用视频需求

- 状态：正式实现已完成并通过当前可执行场景的用户验收；外置设备离线与恢复待设备条件具备后补验
- 日期：2026-08-07
- 交互原型：[`../prototypes/offline-library/index.html`](../prototypes/offline-library/index.html)
- 既有离线规则：[`offline-library-requirements.md`](offline-library-requirements.md)

## 用户目标

用户可以从一个稳定入口查看当前不可用的已索引视频。界面只表达三种状态：正常、离线和无法访问。暂时离线的视频继续自动恢复；无法访问的视频保留本地整理成果，由用户决定重新定位或从 FileFacet 移除。

## 1. 四个预置分类

资料库分组固定显示以下四个预置分类，并保持顺序稳定：

1. 所有视频：`Command-1`
2. 未打标签：`Command-2`
3. 最近添加：`Command-3`
4. 不可用视频：`Command-4`

四个分类始终显示。分类右侧通常显示当前数量；用户按住 Command 时，四个数量临时替换为 `⌘1`、`⌘2`、`⌘3`、`⌘4`，松开 Command、应用失去活动状态或窗口退出资料库界面时立即恢复最新数量。

快捷键只在主资料库界面可用，按下后直接切换对应分类。输入框获得焦点时快捷键仍可使用；包含 Shift、Option 或 Control 的其他组合不触发分类切换。快捷键提示只改变视觉副文案，不改变分类名称、可访问性名称或实际数量。

## 2. 不可用视频分类

“不可用视频”合并展示“离线”和“无法访问”，数量为两者的去重总数：

### 2.1 暂时离线

- 沿用现有离线资料库规则和自动恢复行为。
- 视频继续出现在所有视频、原标签、搜索和其他适用分类中。
- 卡片显示“离线”，Inspector 显示未连接的来源；依赖原文件的操作不可用。
- 设备重新接入且授权恢复后，视频自动离开“不可用视频”，无需用户处理。

### 2.2 无法访问

- 应用无法继续访问原文件且来源卷仍在线时，卡片和 Inspector 统一显示“无法访问”。界面不展示授权、Bookmark、持续访问或确认失效等内部原因。
- 内部仍区分“访问连接丢失”和“文件离开已知位置”。访问连接丢失不写入持久失效字段，视频继续出现在适用的活跃结果中；来源健康且所有已授权位置均找不到文件时，记录持久不可用并从所有活跃结果中移出。
- 文件移动到所有授权范围之外或系统废纸篓时，视为离开已知位置；界面不推断文件是否已经从整个 Mac 永久删除。
- App 开启时将正常视频或其已授权文件夹移入废纸篓后，FileFacet 静默更新状态，不显示全局通知。视频离开所有视频、未打标签、最近添加、标签结果和智能分类结果，只显示在“不可用视频”。
- 保留文件名、现有预览图、原有标签、媒体信息、文件最后一次可访问时记录的原位置和内部确认时间。最后已知位置不得更新为废纸篓路径。
- 卡片显示“无法访问”，排列在暂时离线的视频之前。
- 用户可以重新定位原文件，或执行“从 FileFacet 移除”。
- 原文件以相同身份重新出现在已授权位置时，系统自动恢复视频及其原标签。
- 一个视频存在多个位置时，只要任一位置可以访问，视频保持正常。
- 外置设备先离线时继续显示“离线”；设备重新接入后再根据文件是否存在以及是否位于废纸篓更新状态。

## 3. 用户处理

### 3.1 重新定位

- “重新定位原文件…”打开系统文件选择器，用户选择当前视频文件。
- 用户完成选择后，主要按钮立即进入“正在核对所选文件…”状态并禁止重复点击；结果必须显示在当前窗口内，不依赖窗口标题或副标题。
- FileFacet 只有在完整内容指纹一致时才能自动确认所选文件与原记录相同。文件名、路径、大小、日期、时长、分辨率或文件系统标识均不得单独作为自动通过依据。
- 完整内容指纹不一致、历史记录缺少可比较指纹或现有证据不足时，FileFacet 不自动连接，显示“所选文件与原记录不完全一致”确认界面。
- 确认界面只展示可以帮助用户判断的差异，例如文件名、时长、分辨率和大小；默认操作为“重新选择”，同时提供“取消”和低权重的“仍然连接”。
- 用户选择“仍然连接”后，保留原有标签和首次入库时间，媒体信息、缩略图、文件身份和位置按所选文件更新。
- 内容指纹一致时将记录恢复为可访问状态，并保留原有标签、首次入库时间和既有媒体信息。
- 成功后通知栏显示“已重新连接”，视频恢复到正常分类，通知可以主动关闭。
- 所选文件已经属于另一条视频记录时，通知栏显示“所选文件已存在于 FileFacet”，提供“查看已有视频”，当前失联记录保持不变；点击后进入已有记录所属的预置分类，选中该记录并滚动到其位置。
- 选择不支持的视频、无法完整读取、无法解析为有效视频或其他处理失败时，必须在更新记录前终止；通知栏显示用户可以理解的原因，并提供“重试”或关闭。
- 重新定位终态通知属于当前浏览上下文；用户切换标签或分类、主动关闭通知或退出 App 后结束。关闭通知只结束反馈，不改变已经完成的数据结果。

### 3.2 从 FileFacet 移除

- 单选和多选均可操作，确认信息明确说明将删除 FileFacet 中保留的标签和媒体信息，不影响 Mac 上可能存在的原文件。
- 完成后沿用现有单步撤回和 `Command-Z` 生命周期。
- 用户主动从正常资料库执行“从资料库移除”时继续直接进入现有移出流程，不进入“不可用视频”。

## 4. 展示与可访问性

- “不可用视频”使用一个稳定的系统图标，分类内只通过“无法访问”和“离线”徽标区分用户可见状态。
- 无法访问的视频使用现有预览图和弱化蒙层；离线视频沿用现有离线蒙层。
- Inspector 对无法访问的视频显示最后已知位置；离线视频显示未连接的来源。完整路径不可恢复的既有记录使用“最后已知文件”标注文件名，避免把文件名表达为位置。
- “无法访问”处理页只显示状态、最后已知位置、内容保留承诺和两个操作，不重复解释访问失败，也不显示实现层权限术语。
- 浏览“不可用视频”时，Inspector 使用“处理｜详情”两个模式并默认打开“处理”；“标签”模式隐藏。离开该分类后恢复现有“标签｜详情”。
- “处理”完整占用 Inspector 内容区：无法访问的视频突出显示全宽“重新定位原文件…”主要按钮，并提供低权重的“从 FileFacet 移除…”；离线视频显示自动恢复说明，不提供重新定位。
- 多选不可用视频时，“处理”显示各状态数量，只提供批量移除；重新定位始终逐个完成。
- 无法访问视频的右键菜单优先显示“重新定位原文件…”，底部提供移除；当前无法执行的原文件操作不显示。
- Command 提示出现和消失不触发 VoiceOver 实时播报；每个预置分类的可访问性帮助持续包含对应快捷键。

## 5. 验收标准

1. 四个预置分类顺序固定，`Command-1` 至 `Command-4` 可以直接切换。
2. 按住 Command 时只有四个预置分类右侧的数量变成快捷键提示，松开或应用失去活动状态后恢复最新数量。
3. 外置卷离线后，视频仍保留在原分类并同时进入“不可用视频”；卷恢复后自动离开该分类。
4. 来源健康且确认文件离开已知位置后，视频只出现在“不可用视频”，状态显示“无法访问”，原有标签、现有预览图和媒体信息仍可查看。
5. 无法访问的视频可以重新定位并恢复，也可以单选或批量从 FileFacet 移除。
6. 暂时离线不会被写成持久不可用状态；访问连接丢失时界面同样显示“无法访问”，并可通过重新定位恢复。
7. 英文和简体中文文案完整，快捷键提示与实际菜单快捷键一致。
8. 构建成功只证明代码和资源可编译；上述状态、交互与视觉结果由用户验收。
9. 在“不可用视频”中选中视频后默认看到“处理”，无需滚动即可识别当前状态和主要操作；“详情”继续用于核对原文件信息。
10. 重新定位期间主要按钮显示“正在核对所选文件…”且不可重复点击；成功、文件已存在和其他失败均提供明确反馈。
11. 完整内容指纹一致时可以自动连接；证据不足或内容不一致时必须由用户确认，文件名、路径和媒体属性均不能单独触发自动连接。
12. 差异确认默认引导用户重新选择；用户明确选择“仍然连接”后，原有标签和首次入库时间保留，媒体信息与缩略图按新文件更新。
13. 文件已存在反馈可以直接“查看已有视频”，且不会覆盖当前失联记录；终态通知可以主动关闭，并在切换浏览上下文后结束。
14. App 开启时把正常视频移入本机或已挂载外置卷的废纸篓后，视频静默离开活跃结果并进入“不可用视频”，显示“无法访问”，最后已知位置保留移动前的原位置；外置设备离线仍保持“离线”。
