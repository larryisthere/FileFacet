# 一键恢复：现状核对与技术方案草案

日期：2026-09-14。状态（2026-09-21）：交互方向与 HTML 重新定位主路径已验收；正式代码已实现，用户曾编译启动通过。自动恢复保护及过期媒体回写已补强，补强版本已在独立 App 构建，并通过自动恢复及过期媒体回写两个针对性人工案例。本文记录源码静态证据与推荐边界，不代表运行验证。

## 需求与范围

恢复前按现有记录筛选访问失效/原位置状态不确定的视频；排除确认缺失和设备离线。点击一键恢复后，优先使用已有有效访问，否则请求原位置父目录的精确授权。内容一致才自动连接，成功视频移出不可用列表。部分失败、全失败、停止均汇总结果，保留已提交成功项。文件移动、内容不同、缺少原指纹、重复记录冲突交给现有逐文件处理；不做标签完整性验收、不导入新视频、不改原文件。

| 位置 | 已确认事实 | 设计影响 |

| `performRelink` | 文件发现、完整哈希、数据库评估、媒体检查、用户差异确认、二次哈希、提交、刷新耦合在一起 | 拆出窄的核对与提交能力，保留单文件交互层 |

`lastKnownPath` 可保留无法解析 Bookmark 的原位置；`fallbackPathKey` 是路径哈希，不能反解路径。现有测试有单文件 exact-match 重连用例，尚未执行，不能据此声称覆盖批量恢复。

## 推荐方案

### 1. 参与集合与权限范围

点击时抓取按 videoID 去重的任务快照，不做全盘/全目录预扫描。排除持久 missing、已明确离线及已有有效位置的视频。原位置通过最后已知绝对路径或可解析来源加相对路径取得；路径证据缺失时返回需要重新定位，不能猜测路径。旧卷标识在重装后可能变化，不能只依靠标识不匹配排除本地记录；结合明确外置位置和当前挂载信息，证据不足保持未知。

授权按实际原文件父目录去重。同目录多视频只请求一次，不自动合并为更大祖先目录。有效既有权限可直接使用。新 NSOpenPanel 指定 directoryURL、只允许目录、显示明确用途，并验证返回目录精确匹配（拒绝符号链接/别名及意外更大范围）；无法预定位时允许用户在系统窗口确认目标，不另加应用选择页。HTML 的“允许访问”是概念演示，不保证原生系统完全相同。

### 2. 精确检查与窄复用

新增恢复任务协调状态，沿用 Bookmark 生成和 scoped resource 生命周期基础能力；临时访问句柄先局部持有，不立即加入普通解析/扫描/watcher。按已知位置读取普通受支持文件，排除废纸篓、符号链接和越界路径。

复用单文件发现及媒体检查、完整内容指纹、assessRelinkVideo 和事务内复核。构造相对于授权目录的 DiscoveredVideo；匹配时不导入 Finder 标签。不完整可读、缺指纹、内容不同、归属另一记录分别记录终态；批量流程不弹逐文件强制连接确认。单文件重新定位继续处理这些情况。首版保留提交前再次核对的现有策略，并重新检查文件属性；不声称两次哈希能消除所有文件并发变化风险。

每个成功视频一个事务。既有来源授权、位置关联和恢复保护状态的提交边界应保证崩溃后不会形成“显示成功但没有持久访问”的状态。exactMatch 保留已有媒体与首次入库信息；已有媒体完整时不重新生成缩略图。只对确有缺失的媒体产物使用现有补齐管线。

### 3. 尚未核对项的持久保护（必要扩展）

推荐为 video_locations 增加默认关闭的 `requires_recovery_verification` 标志，旧库迁移保持原行为。授权前为受影响的失效旧位置标记；保护在一键恢复接管目标或访问刷新明确发现来源连接失效时建立；只标记对应失效位置。启动期间暂缓维护调度，先落库保护；后续维护若已有授权覆盖原位置，则先核对内容再连接。正常已验证位置和明确离线项保持原行为。已可用的独立位置不受影响。原位置和旧指纹保留。

保护必须同时作用于：普通 URL 解析、静默维护写入、手动导入的已有记录更新、后台媒体/指纹回写。路径/身份判重仍能识别记录已存在，不能因保护过滤而把同一位置作为新记录插入。对只有受保护位置的视频，维护或导入不得按路径自动更新。此处应采用数据库层统一写入检查，避免仅依赖 UI 按钮互斥。

成功事务添加已验证位置，并使旧的不可信关联不再提供访问；旧位置证据按范围保留，不能直接清除所有旧位置保护。单文件明确重连也需兼容这一事务。部分失败/取消后保护继续保留，重启不会因目录权限已经有效而自动显示成功。验证保护不等同于文件 missing。

开始恢复前取消并等待可能写入目标的维护任务及相关媒体任务退出，再建立保护；恢复期间合并维护请求，结束后调度一次。停止传播到子任务，检查数据库提交边界；已提交项计成功，未提交项计未检查。原型中的 sessionStorage 无法验证这些约束。

### 4. 来源用途与扫描警告

恢复权限默认不新增扫描范围。推荐增加 `scan_policy_explicit INTEGER NOT NULL DEFAULT 0`，继续使用 scans_descendants。旧记录默认 0，沿用原来的目录自动识别行为；新恢复来源保存 explicit=1、scans_descendants=0。手动导入/选择扫描目录明确保存 explicit=1 和对应扫描用途。普通 Bookmark 刷新必须原样保留用途字段。

同一目录已有扫描用途时保留原用途，不能由恢复把扫描关闭。恢复到相同目录的旧来源与授权范围较大的旧祖先来源分别处理，不因恢复子目录而升级整个祖先扫描覆盖。这个方案无需迁移时访问文件系统或解析所有旧 Bookmark。

首版保留旧来源，不做大范围清理。恢复视频已可用与扫描目录可扫描分别判断：子目录授权不能据此声称旧祖先扫描范围已经完整恢复。精确同目录新授权可作为旧扫描范围的有效覆盖；部分覆盖仍提示未检查范围。扫描提示中的恢复入口仅在有可恢复视频时显示；纯扫描失败继续提供扫描目录处理入口，避免恢复完成后出现死按钮。

### 5. UI 与结果

复用当前列表、分类刷新及通知样式，新增批量进度/结果模型（本次总数、成功、失败、未检查）。计数按视频；一个视频有多个原位置时，任一位置核对一致即可成功，失败位置不重复计数。系统取消结束当前恢复；已完成结果保留。参与项全部成功不代表离线与已缺失项也恢复。长任务节流刷新，分类切换不取消任务；原型中结果文案保持在当前上下文的规则与原有通知生命周期对齐。

## 实现前需要收敛的项目

1. **原生授权可行性**：本机单目录精确预定位、确认读取及重启恢复已由用户完成实验。多目录、外置卷及不匹配目录拒绝仍待后续验收。
2. **迁移边界**：采用位置核对标记与来源用途显式标记；默认值保留旧记录行为。需要同步移除/撤回快照的字段，以免撤回丢失保护或用途。
3. **扫描目录覆盖**：不扩大授权意味着祖先扫描范围可能仍不完整，恢复结果与扫描警告应各自准确。本方案推荐保留这一边界。
4. **原型补齐**：缺少历史指纹、归属其他记录的结果入口，及真实系统授权效果尚未完成用户验收；不把原型计时动画当作平台能力证明。

## 验收与后续顺序

当原文件可读且完整指纹一致时，应恢复原记录并持久保持可用；当内容不一致/不可判定时，应留在不可用列表；当用户停止时，应保留已提交结果；重启和后续维护不得绕过剩余项核对。新候选不自动导入、旧失效来源不误判扫描覆盖。

原生单目录授权已验收；按配套实施计划补齐正式版本验收。正式实现后的首个人工案例仍为一个原目录中多个旧视频一起恢复。测试代码需用户验收和当轮授权；重点覆盖事务拒绝、路径正确性、多位置去重、取消/重启及维护绕过，排除标签完整性验证。

## 2026-09-21 收尾补强

启动自动恢复与手动恢复共享两次指纹/媒体核对。自动路径仅使用现有有效权限，无新增系统授权窗口；核对不通过保持保护。同一会话按原文件路径、来源、大小、修改时间和原指纹记住已检查的失败项，输入不变时不重复全文件核对，显式一键恢复不受此记忆限制。

媒体任务开始时读取记录及有效位置快照，提交时在事务中比较；记录、更新时间、位置或保护状态变化则拒绝旧结果。拒绝后仅当存在不同的有效新快照才重新排队。每次新生成的图片使用独立标识，旧任务不覆盖既有图片；取消、失败或拒绝时清理自身新产物，复用图片不随失败任务删除。此补强不增加 schema 版本。
