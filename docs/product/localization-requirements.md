# 中英双语与本地化 Requirements

状态：已确认并通过用户验收（2026-07-30）

关联问题：[OQ-002：中英双语与本地化基础](open-questions.md#oq-002中英双语与本地化基础)

视觉稿：[中英双语视觉与状态原型](../prototypes/localization/index.html)

## 1. 目标

FileFacet 为英文和简体中文用户提供完整、等价的核心体验。用户可以在 macOS 系统语言或单 App 语言设置下完成导入、浏览、搜索、标签管理、设置、应用锁、错误恢复和辅助功能操作。

英文作为开发语言和默认回退语言。系统首选语言匹配简体中文时显示简体中文；繁体中文及其他未支持语言显示英文。

## 2. 用户故事

1. 作为英文用户，我希望从下载后的第一次启动开始看到完整英文界面，从而无需理解中文即可导入并整理视频。
2. 作为简体中文用户，我希望现有核心流程继续显示自然、准确的简体中文。
3. 作为使用其他系统语言的用户，我希望界面稳定回退英文，从而不会出现空文案、key 或中英混杂。
4. 作为拥有自定义标签和文件名的用户，我希望切换界面语言后自己的数据保持原样。
5. 作为使用 VoiceOver 的用户，我希望控件名称、提示和当前状态与界面语言一致。
6. 作为使用窄窗口的用户，我希望英文长文案不会遮挡操作、互相重叠或隐藏关键反馈。

## 3. 语言行为

### 3.1 支持范围

- 当前版本支持英文 `en` 和简体中文 `zh-Hans`。
- 英文为开发语言和默认回退语言。
- 应用跟随 macOS 语言设置，不新增应用内语言选择器。
- 用户可使用 macOS 的单 App 语言设置切换 FileFacet 语言。
- 日语、韩语、繁体中文、德语、法语及其他语言留待真实用户需求或上架要求出现后评估。

### 3.2 一致性

- 同一窗口、菜单、弹窗或状态区域不得混合显示英文和简体中文系统文案。
- 产品名称 `FileFacet` 保持不变。
- Finder、Touch ID、Mac、macOS 等平台名称遵循 Apple 的正式写法。
- 未找到翻译时使用英文默认值，界面不得展示本地化 key。

## 4. 用户数据边界

以下内容保持用户原值：

- 标签名称及标签层级
- 文件名与文件扩展名
- 文件路径
- 资料库中来自 Finder 的标签
- 用户输入和系统文件元数据

用户数据只能作为完整本地化句子的参数。界面语言变化不得改写数据库中的用户内容，也不得改变标签身份、排序持久化值或筛选条件。

## 5. 用户可见范围

### 5.1 macOS 菜单与窗口

- App、文件、编辑和窗口菜单
- 关于、设置、退出、导入、新建标签、撤销、最小化等命令
- 菜单快捷键保持系统约定
- 主窗口 Toolbar、搜索框、缩略图大小和侧栏显示控制

### 5.2 资料库与导入

- 空资料库提示
- 导入选择器标题、说明和按钮
- 导入扫描、保存、取消、完成、部分失败和空结果
- 新增、已存在、失败及无法读取数量
- 从资料库移除、撤回和恢复反馈
- 默认播放器与 Finder 操作

### 5.3 标签

- 资料库与标签分组标题
- 全部视频、最近添加和未打标签
- 标签排序方式、颜色和右键菜单
- 新建、重命名、删除、移动、合并和校验错误
- 检查器中的标签搜索、三态选择、草稿摘要、应用和取消
- 用户标签名称保持原值

### 5.4 详情、设置和应用锁

- 视频格式、大小、时长、分辨率、日期和路径标题
- 隐私与关于设置
- 应用锁、闲置时间、Touch ID 和系统验证
- 版本、构建号、最低系统要求及本地只读说明

### 5.5 错误与辅助功能

- 用户可见数据库、授权、导入、筛选和标签错误
- Tooltip
- VoiceOver Label、Value、Hint 与系统图标描述
- 等待、成功、失败、禁用和选中状态

## 6. 动态内容与系统格式

- 数量文案通过 String Catalog 复数规则生成；英文至少覆盖 `one` 和 `other`。
- 完整句子一次本地化，不拼接依赖某种语言语序的名词、动词、标点和状态片段。
- 多段结果摘要使用可本地化的列表格式或完整模板。
- 日期、数字和文件大小使用当前 Locale。
- 媒体时长继续使用通用的 `mm:ss` 或 `hh:mm:ss`。
- 用户标签按名称排序时继续使用当前 Locale 的自然比较。

## 7. 布局与视觉要求

- 主窗口继续使用现有原生三栏结构和系统强调色。
- 英文长文案优先通过 intrinsic content size、弹性宽度、合理换行和系统截断策略适配。
- 关键按钮、状态标题、错误原因和恢复动作必须保持可见。
- Toolbar 在窄窗口下遵循 AppKit 的溢出行为。
- 侧栏和检查器允许用户按当前产品规则调整宽度；内容区域承担主要弹性空间。
- 语言切换不改变信息层级、图标含义、功能入口和操作顺序。

## 8. 范围边界

本轮包含：

- 英文和简体中文 String Catalog
- 全部用户可见系统文案
- 动态句式、复数和列表格式
- 展示文字与业务身份解耦
- 英文长度引起的必要布局调整
- README、CHANGELOG、Issue 模板和 Release Notes 的语言对齐

本轮暂不包含：

- 应用内语言选择器
- 第三种语言
- 远程文案或翻译平台
- 机器翻译批量发布
- 新的应用功能或信息架构
- 标签、文件名和路径翻译

## 9. 验收标准

1. 英文环境中的菜单、主窗口、导入、标签、设置、应用锁、错误、Tooltip 和辅助功能文案全部显示英文。
2. 简体中文环境中的相同范围全部显示简体中文。
3. 繁体中文及其他未支持语言环境完整回退英文。
4. 任一核心流程中不出现空字符串、本地化 key 或无意的中英混合。
5. 零个、一个和多个对象的英文数量文案语法正确。
6. 切换语言后，用户标签、文件名、路径和数据库身份保持不变。
7. 日期、数字和文件大小符合当前 Locale。
8. 英文长文案不造成按钮遮挡、文字重叠、关键反馈不可见或无法操作。
9. VoiceOver 读出的控件名称、状态和提示与当前界面语言一致。
10. 工程重新生成后，String Catalog 仍在 App target 的 Resources 中。
11. 默认 Debug 构建成功；界面语言、布局和辅助功能结果由用户验收。
