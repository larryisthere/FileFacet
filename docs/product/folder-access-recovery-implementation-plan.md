2026-09-14 起草，2026-09-21 收尾完成。HTML 主路径、导航调整、日常缩略图体验、独立自动恢复案例和过期媒体回写案例已由用户确认；独立验收 App 构建通过。多目录与外置卷等更广场景未单独验收，未执行自动化测试。

## 范围与收敛决定

1. 仅复用核对、授权基础能力、事务连接与刷新；不调用整条扫描导入或 performRelink UI 流程。
2. 保护一键恢复接管的位置，以及访问刷新明确识别的连接失效位置；保持正常位置及明确离线重连规则。已有权限覆盖时自动核对后连接。
3. 位置新增 requires_recovery_verification，来源新增 scan_policy_explicit；均默认 0。旧数据不访问原文件、不删除旧来源。来源用途显式时以保存值为准。
4. 每条恢复成功原子保存授权、更新位置/记录及核对状态。旧受保护位置保留定位证据；未核对位置不能提供访问。已核对的独立位置使视频保持可用。
5. 内容不一致或无历史指纹不得更新旧指纹；按现有重新定位入口处理。缺失与权限错误分别判断，单纯 fileExists=false 不足以写持久 missing。

## 写入边界核查

- `importVideos` 调用 updateVideo/upsertLocation：识别为已有受保护记录时不能直接更新。返回已有/需恢复的结果，不重复创建；后续导入 UI 不应把它计作恢复成功。
- `reconcileSources` 调用 updateVideo/removeOtherLocations/upsertLocation：匹配受保护位置时保留该记录，不执行写入和删除位置。stale-location 与缺失确认也不能把“待核对”自动升级为 missing。
- `relinkVideo`：复用事务内 exactMatch/needsConfirmation/existingRecord 规则；成功位置解除对应保护，保留无关位置证据。手动确认替换继续保留现有授权边界。
- `updateMediaInfo`：现有 WHERE id 没有核对状态约束。来自待核对位置的迟到结果不可回写指纹及媒体。提交携带来源/位置与任务版本并复核，避免旧任务在新恢复结果后覆盖；不以一个宽泛 available 状态代替来源校验。
- `confirmMissingLocations`、维护最终 missing 汇总：只针对已获得读取证据的真实缺失，保护项不能由空枚举结果推定删除。
- 移除/撤回：快照恢复需携带新增字段；此为新增字段完整性维护，不改变已有移除交互。

位置保护标志与 is_available 分工：前者表示该位置需要核对，后者保留现有位置存在状态。普通解析排除保护位置；可用性统计需统一使用同一有效位置条件。判重查询仍保留受保护位置，以免重新导入重复记录。

## 建议接口与任务边界

命名为设计草案，实施可贴合现有类型。

- `planAccessRecovery()`：读取位置、最后已知路径和可用性，生成按 videoID 去重的工作集合与精确父目录组；不请求授权、不枚举目录。
- `requestRecoveryDirectory(expectedURL:)`：预定位系统窗口，检查精确返回目录；返回局部持有的访问句柄及 Bookmark，不立即启动 watcher。
- `inspectRecoveryCandidate(videoID:location:)`：单文件发现、目录相对路径转换、取消传播、内容与媒体核对；返回结构化结果，无单文件弹窗。
- `commitVerifiedRecovery(...)`：事务内重新评估记录及指纹，保存来源/位置并更新对应保护；事务成功是唯一成功计数依据。
- `RecoverySession`：协调集合、授权/核对阶段、当前子任务、成功/失败/未检查数量。前台恢复与导入、单文件重连互斥；维护先取消并等待退出，结束后合并调度一次。启动初始化完成前暂缓维护，防止保护尚未落库就进行路径匹配。

对受保护的视频，若存在独立已核对位置，可继续从该位置读取；对候选文件的自动写入仍检查其位置证据。不能仅因某个视频有可用副本便接受另一未核对位置。

## 验证边界

首个正式人工案例：一个目录内多个 accessLost 视频，选择一键恢复并确认原目录，内容一致项恢复、无重复新增。随后每次单独验收部分失败、取消、重启、多位置及扫描维护交错。

关键风险检查：新来源相对路径；用户取消后成功项持久化；新目录授权不会使未核对项自动可用；后台写入不覆盖旧指纹；旧扫描用途保持；纯恢复目录重启后不自动纳入扫描；未确认缺失不会被写成 missing。

本计划无构建、测试或 App 启动授权含义。本轮仅代码阅读、文档更新及 git diff --check。
