# 不可用视频设计

- 状态：正式实现已完成并通过当前可执行场景的用户验收；外置设备离线与恢复待设备条件具备后补验
- 需求：[`unavailable-videos-requirements.md`](unavailable-videos-requirements.md)
- 交互原型：[`../prototypes/offline-library/index.html`](../prototypes/offline-library/index.html)

## 状态模型

```text
可访问
  ├─ 卷暂时断开 ───────────────▶ 离线（运行时）
  │                               └─ 卷恢复 ─────▶ 可访问
  ├─ 访问连接恢复失败 ─────────▶ 无法访问（内部原因：访问连接丢失）
  │                               ├─ 用户重新定位 ▶ 可访问
  │                               └─ 用户移除 ────▶ 删除记录
  └─ 健康来源确认找不到文件
     或文件位于系统废纸篓 ─────▶ 无法访问（内部原因：离开已知位置）
                                  ├─ 自动重新发现 ─▶ 可访问
                                  ├─ 用户重新定位 ─▶ 可访问
                                  └─ 用户移除 ─────▶ 删除记录
```

`VideoRecord.Availability` 只包含 `available`、`offline` 和 `unavailable` 三种用户状态。`VideoRecord.UnavailableReason` 使用 `accessLost` 与 `missingFromKnownLocation` 保存内部原因。数据库继续使用 `availability_status = 'missing'` 表达持久的“离开已知位置”，读取时映射为 `.unavailable`；访问连接丢失由 `LibraryAccessCoordinator` 在运行时装饰为 `.unavailable`。

## 内部不可用原因

- `source_authorizations` 中存在保存的 Bookmark、来源卷仍在线、当前进程却没有成功建立对应文件访问连接时，该来源成为 `accessLost` 候选。
- 同一视频只要从任一位置解析到真实可访问 URL，就保持可用；其余候选不影响展示状态。
- 展示优先级为无法访问、离线、正常；内部原因不改变界面文案。
- `accessLost` 视频继续参与活跃查询，同时与持久不可用和离线视频按 ID 合并计入“不可用视频”。
- 用户重新定位 `accessLost` 视频时允许底层仍为 `available` 的当前记录更新来源；选择已属于另一条记录的文件仍拒绝覆盖。

## 持久不可用与废纸篓

- 静默维护确认文件已经离开所有健康授权范围后，将视频标记为 `missing`，并记录 `invalidated_at`；该字段和时间属于内部数据，不形成独立用户状态。
- 访问解析使用系统废纸篓目录定位结果，并以路径组件规则覆盖本机 `~/.Trash`、启动卷 `/.Trashes` 和外置卷 `/Volumes/<卷名>/.Trashes`。来源卷在线且已保存的 Bookmark 明确解析到废纸篓根节点时，该路径本身足以确认持久不可用；文件夹来源下的候选文件仍需有效访问连接后确认。
- 来源根节点或候选文件位于废纸篓时，不加入 `resolvedVideoURLs` 和 `reachableSourceIDs`，并进入缺失确认；来源卷离线的判断优先，设备重新接入后再确认废纸篓状态。
- `resolveLastKnownVideoPaths` 跳过位于废纸篓的来源 URL；数据库已有的历史路径也会经过相同检查。可用的移动前路径继续显示，已被旧版本污染为废纸篓地址的记录降级显示文件名，避免把废纸篓地址表达为最后已知位置；文件回到正常位置后重新记录真实路径。
- `video_locations.last_known_path` 在文件可访问时保存标准化完整路径；确认离开已知位置时保留该值并将 `is_available` 设为 `0`。`video_tags`、媒体信息和缩略图引用继续保留。
- Schema 11 为既有位置增加 `last_known_path`。升级时优先使用已解析来源 URL 回填；URL 无法解析时读取 Bookmark 创建时封装的路径资源值。Bookmark 本身不含路径值且数据库没有完整路径时保留空值。
- 活跃查询继续限定 `availability_status = 'available'`；不可用查询返回持久 `missing`，再与运行时离线视频按视频 ID 合并去重。
- 同一视频仍有其他可访问位置时保持 `available`。
- 重新发现相同文件身份或用户完成重新定位后，更新位置、清空 `invalidated_at` 并恢复 `available`。
- 用户确认从 FileFacet 移除时复用现有移出快照、撤回与孤儿资源清理。

## Sidebar 与查询

- `LibraryFilter.offline` 扩展为统一的不可用范围，正式实现时使用能表达产品语义的名称，例如 `unavailable`。
- 侧栏固定建立所有视频、未打标签、最近添加和不可用视频四个节点。
- 不可用数量由持久不可用 ID、运行时 `accessLost` ID 与运行时离线 ID 的并集产生。
- 不可用结果中，无法访问的视频优先，组内沿用当前用户排序；相同视频不会重复出现。
- 持久不可用视频不进入活跃标签计数、搜索结果和智能分类；`accessLost` 与离线视频继续参与适用的活跃结果。

## 快捷键与提示

- App 主菜单为四个分类注册 `Command-1` 至 `Command-4`，由菜单命令进入现有导航入口，保持系统快捷键发现与校验行为。
- 资料库界面监听本应用内的 Command 修饰键变化，只驱动四个预置节点的尾部显示。
- Command 按下时，尾部从数量切换为固定提示；松开、窗口失去 key 状态、应用 resign active 或离开资料库界面时恢复数量。
- 数量在提示期间发生变化时直接更新模型；恢复显示时呈现最新值。
- 标签和智能分类的尾部数量不参与快捷键提示。

## Video Grid 与 Inspector

- 离线卡片继续显示“离线”徽标和现有蒙层。
- 两种内部不可用原因统一显示“无法访问”徽标和相同蒙层；Inspector 提供重新定位和移除入口。
- Inspector 根据状态显示当前来源或持久化的最后已知位置；只有真实解析到文件 URL 时才显示“可以访问”。缺少持久化路径的既有记录显示“最后已知文件”和文件名。
- Inspector 模式由当前浏览上下文决定：普通分类使用“标签｜详情”，不可用分类使用“处理｜详情”并默认选择“处理”。
- “处理”是独立内容页，不与标签页底部的应用/取消区域共存，也不追加在详情滚动内容末尾。
- 无法访问视频在处理页提供全宽“重新定位原文件…”主要按钮及低权重移除操作；离线视频显示来源和自动恢复方式。
- 无法访问处理页的信息顺序固定为“无法访问”、最后已知位置、原有标签和媒体信息保留承诺、重新定位、移除。
- 多选处理页只汇总“无法访问”和“离线”数量，只提供批量移除，不提供批量重新定位。
- 不可用视频右键菜单按用户状态构建；无法访问的单选菜单以重新定位开头，移除位于底部，无法执行的打开、Finder 定位和复制路径不进入菜单。

## 重新定位反馈

- 用户选定文件后，Inspector 主要按钮进入禁用的“正在核对所选文件…”状态，避免重复提交；完成后恢复普通按钮状态。
- 重新定位结果复用内容区顶部的统一通知栏，保持在当前窗口首屏可见，并提供最右侧独立关闭按钮。窗口标题、副标题和日志不承担用户反馈职责。
- 成功时显示“已重新连接”，随后按恢复后的可用状态刷新分类与选中项。
- 所选文件已属于另一条记录时保持当前失联记录不变，显示“所选文件已存在于 FileFacet”，并提供“查看已有视频”。该操作复用统一的视频显示请求，进入“所有视频”或“不可用视频”，选中已有记录并滚动到该记录。
- 其他失败将底层错误映射为用户可以采取行动的说明，并提供“重试”；不显示 `DatabaseError`、Bookmark 或持续访问权限等实现术语。
- 通知在用户主动关闭、切换标签或分类以及退出 App 时结束。通知关闭不回滚成功结果，也不改变失败后保留的失联记录。

## 内容确认策略

- 新入库视频在后台计算完整文件字节的 SHA-256，并将摘要作为本地内容指纹保存；指纹不进入日志、网络请求或用户可见诊断信息。
- 重新定位在数据库更新前完成受支持类型检查、完整可读性检查、有效视频解析、其他记录冲突检查和内容指纹比较。
- 只有完整内容指纹一致时进入自动成功路径。卷标识、文件资源标识和路径继续用于定位与查重，不代替内容一致性判断。
- 历史记录缺少内容指纹、没有可比较的旧指纹或新旧摘要不一致时进入 `needsConfirmation`，保持原记录和失联状态不变；所选文件无法计算摘要时进入失败结果。
- `needsConfirmation` 使用窗口级确认界面展示原记录与所选文件的可理解差异。默认按钮为“重新选择”；“仍然连接”必须由用户明确触发，不能由超时、回车焦点漂移或后台规则代替。
- 用户确认后在同一个数据库事务中更新文件身份、位置和可用状态，保留标签与首次入库时间，并将媒体信息、缩略图和来源信息标记为按新文件重新生成。
- 内容指纹命中其他视频记录时沿用 `existingRecord` 冲突结果，不提供覆盖；无法读取或无法解析的视频进入失败结果，不提供“仍然连接”。
- 迁移后的既有记录不会凭文件名、路径、文件大小、时长或分辨率推断内容一致；首次重新定位时证据不足即交由用户确认，并在成功后保存所选文件指纹供后续判断。

## 并发与安全

- 单文件来源根节点返回明确的文件不存在错误、Bookmark 已恢复且原卷仍在线时，维护任务将该来源作为已验证空结果处理。
- 权限错误、Bookmark 失效、来源枚举部分失败或卷离线时保持现有记录，不确认文件离开已知位置。
- 状态转换、位置更新和移除继续由 `DatabaseStore` 串行执行。
- 完整路径只保存在本机资料库数据库中，用于用户定位原文件；日志、网络请求和诊断输出继续禁止记录该字段。
- 快捷键导航遵循现有智能分类离开确认；用户取消离开时保持当前分类。

## 原型边界

HTML 原型已验证四个预置分类、Command 提示、三种用户状态、两种内部不可用原因的统一表达、离线恢复、重新定位和永久移除。正式 AppKit 实现、真实文件选择器、数据库迁移和本机文件状态转换已经完成并通过当前可执行场景的用户验收；真实外置设备离线与恢复仍保留为设备验收项。
