# 组合筛选、排序与智能分类设计

- 状态：已实现并经用户验收
- 需求：[`smart-filters-requirements.md`](smart-filters-requirements.md)
- 交互原型：[`../prototypes/smart-filters/index.html`](../prototypes/smart-filters/index.html)

## 设计概览

主窗口继续使用现有 AppKit 三栏结构，在视频网格上方增加规则状态行：

```text
Sidebar selection + Toolbar filename search
                    │
                    ▼
          LibraryQueryRequest
      ┌─────────────┼─────────────┐
      ▼             ▼             ▼
 baseFilter   temporary search  saved rule
                    │
                    ▼
              DatabaseStore
                    │
            results + live counts
```

`LibraryContentViewController` 只负责组合规则状态行和现有视频网格。`LibraryRuleBarViewController` 负责条件摘要、操作入口与 Popover；`LibrarySplitViewController` 持有当前基础范围、临时搜索、工作规则和已选智能分类，避免多个界面组件分别维护查询事实。

## 查询模型

`LibraryQueryRequest` 包含：

- `baseFilter`：全部视频、系统分类或一个 / 多个标签范围。
- `temporaryFilenameSearch`：工具栏临时文件名搜索。
- `rule`：可持久化的条件、关系和排序。

`LibraryQueryRule` 包含：

- `requiredTagIDs`：由标签基础范围持久化得到，始终取交集。
- `requiredConditions`：由“未打标签”“最近添加”等系统基础范围持久化得到，始终取交集。
- `filenameContains`：一个或多个持久文件名包含条件，始终取交集。
- `matchMode` 与 `conditions`：条件组的全部 / 任一关系。
- `sort`：单个排序键与方向。

规则持久化前统一去除空白、重复标签 ID 和重复文件名条件。标签递归匹配在 SQLite 查询中使用局部递归 CTE，查询绑定按谓词生成顺序追加。

## 状态与导航

### 普通分类

- 在系统分类和标签之间切换只更新 `baseFilter`，保留临时搜索与工作规则。
- 标签范围作为只读条件显示，清除操作只清除临时搜索、可编辑条件和排序。
- 保存时把基础范围写入规则：标签写入 `requiredTagIDs`，未打标签和最近添加分别写入 `requiredConditions` 中的 `.untagged` 与 `.addedWithinDays(30)`，避免“匹配任一条件”扩大基础范围。
- 离线范围依赖协调层实时解析磁盘访问状态，保存入口禁用。

### 智能分类

- 进入时载入已保存规则，基础范围设为全部视频，临时搜索清空。
- Popover 内编辑只改变局部草稿，点击“完成”后一次写入工作副本并查询；智能分类数据库记录在用户点击“更新”后变化。
- 工作副本与已保存规则规范化后不同即视为脏状态。
- 离开脏状态时先恢复侧栏原选择，待用户完成更新、放弃或取消后再执行目标导航。
- 更新失败时清除待导航目标，恢复原侧栏选择并保留工作副本。

## SQLite 持久化

schema 9 增加 `smart_collections`：

- 主键 `id`，外键 `library_id`。
- `name` 与用于唯一约束的 `normalized_name`。
- JSON 编码的 `rule_json`。
- `sort_order`、`created_at`、`updated_at`。

智能分类结果不落库。读取智能分类后使用同一查询管线计算当前数量，视频、标签或媒体事实变化后的统一刷新会重新计算数量。媒体信息连续回填时采用短延迟合并刷新，兼顾结果及时性与重复查询开销。

数据库写入由 `LibraryAccessCoordinator` 串行化，避免连续创建、更新和删除相互覆盖。数据库唯一约束作为名称冲突的最终保护。

## UI 映射

### 规则状态行

- 左侧依次显示标题、只读范围、临时搜索、条件关系、条件和排序。
- 每个已添加条件为可点击 Chip，点击打开编辑 Popover；移除按钮只移除对应条件。
- 默认无筛选条件时，“添加筛选”显示文字提示；出现范围、搜索或任一筛选条件后收紧为 28 pt 图标入口。默认排序独立显示“添加排序”文字入口，已有排序显示可编辑的文字 Chip。
- 普通分类右侧使用 `xmark.circle` 图标提供清除，并使用“保存”文字按钮提供紧凑入口；悬停提示和辅助功能标签说明完整的“存为智能分类…”动作。
- 智能分类脏状态显示状态、还原、另存为和更新，并保留文字按钮以明确不同提交结果。
- “编辑”菜单提供“搜索文件名”（`⌘F`）与“添加筛选条件”（`⇧⌘F`）；前者聚焦并选中工具栏搜索内容，后者从规则栏入口打开同一添加菜单。

### Popover

- Popover 使用 320 pt 固定宽度和内容驱动高度，标签列表最多显示约五行并在内部滚动，避免单个条件编辑器扩展为大窗口。
- 每个控件显示“条件”“关系”“标签 / 范围”等短标签；已有条件底部使用左侧移除、右侧取消与完成的稳定操作布局，新条件只显示取消与完成。
- 修改“排序依据”时在原位刷新对应的顺序选项并保持 Popover 打开，点击“完成”后统一应用排序与查询。
- 文件名使用文本输入。
- 新建标签条件使用空的标签复选列表，不继承或预选标签；草稿可以暂时清空，至少选择一个标签后才能完成。
- 日期、时长、大小和分辨率使用有限选项，降低输入错误和实现复杂度。
- 新增具体条件后立即打开对应 Popover；文件名和标签条件在输入有效值前禁用完成，其他条件提供可修改的默认草稿。
- 点击完成时阻止完全相同的文件名或筛选条件；部分重叠的标签条件保持独立，避免自动化简改变全部 / 任一组合语义。
- 点击完成只提交一次工作规则并触发一次查询；取消、`Esc` 或点击外部区域关闭时丢弃草稿，不更新结果或智能分类数据库记录。

### Sidebar

- 智能分类分组位于资料库系统分类与标签分组之间。
- 双击智能分类、右键菜单和行内 `•••` 的“重命名”进入同一行内编辑状态。
- 标签与智能分类复用同一行内重命名生命周期：`Return` 或失焦校验并提交，`Esc` 取消并恢复原名称；空名称或重名时保留编辑状态并重新聚焦。
- 计数与现有系统分类和标签数量使用同一尾部列。

## 本地化与隐私

- 新增文案进入 `Resources/Localizable.xcstrings`，覆盖英文和简体中文。
- 日期选项、时长选项和文件大小使用本地化标题或系统格式化。
- 文件名、标签名和智能分类名称只作为参数显示。
- 日志只记录错误类别，不记录规则值、文件名或标签名。

## 明确排除

- 查询语言、正则表达式、全文索引和多级嵌套条件组。
- 多列排序和拖拽调整智能分类顺序。
- 将运行时离线状态持久化为智能分类条件。
- 智能分类同步、分享、导入或导出。
